## 1. Visible zone bands are drawn at padded size, not icon-cell size

**Severity:** High — makes the wallpaper look broken even when the system works correctly.

**What's happening:**
`WaBiBaBuSy.WallpaperEngine/Desktop/ZonePlanner.cs` (lines 65-80) emits a `ZoneRect` per icon whose width/height include the full `paddingPx` on every side:

```csharp
float zX = Math.Max(0f, px - paddingPx);
float zY = Math.Max(0f, py - paddingPx);
float zW = Math.Min(cellW + 2 * paddingPx, screenW - zX);
float zH = Math.Min(cellH + 2 * paddingPx, screenH - zY);
```

With a 320×320 GIF (`_animHeight/2 = 160`) plus `WaveAmplitudePixels = 100`, `paddingPx = 260`, so every icon paints a **595×595 px** colored block over a 75×75 icon. On a 1080p monitor, five icons can cover ~60% of the screen. Screenshots in `.claude/BrokenIconZones.png` / `BrokenIconZones2.png` show the effect.

**Fix direction:**
Split padding into two concepts:
- **Visual band size** (what `DrawBackground` paints) = `cellW × cellH` (tight icon cell, maybe + a 4–8 px halo for visibility).
- **Pathfinding occupancy** (what A* treats as blocked) = current `paddingPx`.

`ZoneLayout.Bands` should contain only the visual rects; the occupancy grid stays internal to `Compute`. Players keep drawing `_iconZoneBands` as-is. Debug overlay's "ShowIconRects" should additionally draw the padded occupancy (in red) so the user can still see what A* is actually avoiding.

**Files likely to change:**
- `WaBiBaBuSy.WallpaperEngine/Desktop/ZonePlanner.cs` — stop growing `ZoneRect` by padding; add an optional `OccupiedRect` list for debug.
- `WaBiBaBuSy.Player.D2D/Program.cs` `DrawDebugOverlay` — render the occupied rects if the new list is present, fall back to today's behaviour otherwise.

## 2. Desktop icons vanish after screenshot tools / overlay apps

**Severity:** Medium — reproducible, not caused by WaBiBaBuSy, but WaBiBaBuSy makes recovery painful.

**Symptom:** Opening Windows Snipping Tool or other fullscreen overlays briefly disturbs the Progman/WorkerW window tree. When the overlay closes, `SysListView32` has re-registered only a subset of icons — the rest stay invisible until the user refreshes the desktop.

**What makes it worse:**
Because the wallpaper window is parented behind icons (see `CLAUDE.md` → "Windows Desktop Integration"), the **right-click menu on the desktop no longer appears** while WaBiBaBuSy is running. So you can't do the usual "right-click → Refresh" recovery. See `BrokenIconZones2.png` in `.claude/` — user took the screenshot specifically because icons vanished and couldn't be restored.

**Fix direction (pick one, probably in this order):**
1. **Detect the disturbance.** Subscribe to `WM_SETTINGCHANGE` / poll `SHELLDLL_DefView` existence once per second; if the window tree changes, re-parent the wallpaper and refresh icon positions.
2. **Provide an in-app "Refresh Desktop" button** that calls `SHChangeNotify(SHCNE_ASSOCCHANGED, ...)` or posts `F5` to the desktop listview. Exposes recovery without needing the right-click menu.
3. **Restore right-click pass-through.** `WS_EX_LAYERED` with full opacity but `SetLayeredWindowAttributes(..., LWA_ALPHA)` should let mouse clicks go through to the desktop — verify this. If not, consider `SetWindowLong(GWL_EXSTYLE, WS_EX_LAYERED | WS_EX_NOACTIVATE)` behavior on 24H2+. **Do NOT add `WS_EX_TRANSPARENT`** — CLAUDE.md says that crashes explorer on 24H2+.

**Files likely to change:**
- `WaBiBaBuSy.WallpaperEngine/Native/Win32Interop.cs` or `DesktopWindowManager` — add the detection.
- `WaBiBaBuSy.UI/Views/MainWindow.axaml` — add a "Refresh Desktop" button.

## 3. A* path often can't find a way through when padding ≥ icon spacing

**Severity:** Medium — animation falls back to straight line, which may cross icons.

**Context:** `ZonePlanner.ComputeAStarPath` (lines 98-171) allows traversal of occupied cells at cost `50f` as a last resort (line 148). With huge padding, every cell near any icon is occupied, so the "shortest" path accumulates cost by crossing them — the fallback straight line at line 162-170 often wins, which runs from the edge through icon territory.

**Fix direction:**
When all rows on an edge are blocked, expand the start/end search outward (spiral, not just vertical) to find a truly free entry point. Also consider adding cost-based "nudge" passes so the path takes *slightly* occupied cells only when they are on the periphery of an icon, not the center.

This issue largely disappears once Issue #1 is fixed (padding no longer bloats visual bands → configured padding can be lower because the A* and visual are decoupled), but worth tracking.

## 4. Icon cell positions reported by `LVM_GETITEMPOSITION` include invisible icons

**Severity:** Low — cosmetic quirk, harmless after icons re-register.

The Win32 `SysListView32` keeps positions for icons that have been hidden by shell state. After a disturbance (Issue #2), zones get drawn at stale positions while the icons themselves are absent. Matches the oddly-placed coloured rectangles in `BrokenIconZones.png`.

**Fix direction:**
After calling `LVM_GETITEMPOSITION`, also call `LVM_GETITEMRECT` or check `LVIS_HIDDEN` state via `LVM_GETITEMSTATE`. Skip hidden items.

**File:** `WaBiBaBuSy.Core/Services/Desktop/DesktopIconService.cs` plus the local copy in `Player.D2D/Program.cs` `DetectDesktopIconPositions`.

## 5. Debug overlay — info panel still not implemented

**Severity:** Low — overlay already shows path / icons / trail / anim rect / status LED, which is enough for the current bugs.

Plan originally called for a DirectWrite text panel showing monitor index, `_animWidth×_animHeight`, FitMode, path length, FPS. Currently only a green 16×16 LED indicates overlay is on.

**Fix direction:**
Add `Vortice.DirectWrite` reference to `Player.D2D.csproj`, create cached `IDWriteFactory1` + `IDWriteTextFormat` in `InitializeD2D`, and call `_d2dContext.DrawText(...)` from `DrawDebugOverlay` when `ShowInfoPanel` is true. Keep the LED as a fallback when text resources fail to initialise.

## 6. F11 hotkey is not reliable

**Severity:** Low — workaround exists.

Avalonia's main window or some other process sometimes consumes F11 before `RegisterHotKey` on the player HWND sees it. The new **Debug Overlay** button in the main window works around this by sending the stdin command directly, but the hotkey remains half-reliable.

**Fix direction (only if this matters):**
Consider a `WH_KEYBOARD_LL` low-level hook in the main UI process that catches F11 globally and broadcasts via the existing stdin IPC. More invasive than `RegisterHotKey` but immune to focus.

# Rendering Research - Alternative Approaches to Fix Windows 11 24H2 DXGI Issue

**Date:** 2026-01-18
**Status:** Research Complete
**Priority:** P0 CRITICAL - Blocking GIF animation display

## Problem Summary

DXGI swap chain on Windows 11 24H2 (Build 26100.7623) displays only the first frame when window is parented to desktop WorkerW. Backend pipeline works perfectly (LibVLC decoding, composition, render loop), but **Desktop Window Manager (DWM) is not compositing updated frames to the display**.

**Current Architecture (BROKEN on Win11 24H2):**
```
LibVLC → Composition → D2DPlayer.exe (DXGI swap chain) → WorkerW → ❌ FROZEN DISPLAY
```

## Research Area 1: Flip Model Swap Chains

### What is Flip Model?

Flip model (introduced in Windows 8) allows back buffers to be **shared directly with DWM**, eliminating copy operations and improving performance. In flip model, all back buffers are shared with the Desktop Window Manager, allowing DWM to compose straight from those back buffers without additional copy operations.

**Two flip model types:**
1. **`DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL`** - Traditional flip presentation
2. **`DXGI_SWAP_EFFECT_FLIP_DISCARD`** - More flexible, recommended for Windows 10+

### Key Requirements & Limitations

**From Microsoft Documentation:**

> Flip model should be used in an HWND that is not also targeted by other APIs, including DXGI bitblt presentation model, other versions of Direct3D, or GDI.

> After the first successful call to Present on a flip-model swap chain, **GDI no longer works with the HWND** associated with that swap chain, even after destruction of the swap chain.

**Critical Constraint for Wallpapers:**
- Cannot mix flip model with GDI (which many Windows Forms controls use)
- Once flip model swap chain is created, the HWND is "locked" to DXGI
- **Our current approach uses pure Win32 window** ✅ (no GDI contamination)

## Research Area 2: DirectComposition API

### What is DirectComposition?

DirectComposition is a Windows component that enables high-performance bitmap composition with transforms, effects, and animations. It was designed specifically for scenarios like **desktop wallpapers and overlays**.

**Key Advantage:** DirectComposition is purpose-built for compositing content **onto the desktop**, unlike DXGI which is designed for full-screen rendering.

### How It Works

```csharp
// 1. Create DirectComposition device
IDCompositionDevice dcompDevice;
DCompositionCreateDevice(d3dDevice, out dcompDevice);

// 2. Create composition target for window
IDCompositionTarget target;
dcompDevice.CreateTargetForHwnd(hwnd, topmost: false, out target);

// 3. Create visual tree
IDCompositionVisual visual;
dcompDevice.CreateVisual(out visual);

// 4. Bind DXGI surface to visual (use swap chain or texture)
visual.SetContent(dxgiSurface);

// 5. Set visual as root of composition
target.SetRoot(visual);

// 6. Commit changes
dcompDevice.Commit();

// 7. Update frames
// When new frame is ready:
dxgiSurface.Present(...);  // Update surface
dcompDevice.Commit();      // Commit changes to composition
```

### Windows 11 24H2 "Raised Desktop" Compatibility

**From Lively Wallpaper's Implementation:**

Lively detects the new Windows 11 "raised desktop with layered ShellView" mode:

```csharp
// Lively's approach (WinDesktopCore.cs:148)
isRaisedDesktopWithLayeredShellView = WindowUtil.HasExtendedStyle(
    progman,
    NativeMethods.WindowStyles.WS_EX_NOREDIRECTIONBITMAP
);

if (isRaisedDesktopWithLayeredShellView)
{
    // Microsoft's guidance for Windows 11 24H2+:
    // "Create a WS_EX_LAYERED child HWND that is z-ordered under DefView
    //  but above WorkerW. Use SetLayeredWindowAttributes(bAlpha=0xFF)
    //  to enable DX blt presents without performance issues."

    WindowUtil.SetWindowStyle(hwnd, NativeMethods.WindowStyles.WS_CHILD);
    WindowUtil.SetWindowTransparency(hwnd, 255);  // WS_EX_LAYERED + full opacity

    WindowUtil.TrySetParent(hwnd, progman);  // Parent to Progman, NOT WorkerW

    // Z-order: Place under DefView, above WorkerW
    NativeMethods.SetWindowPos(hwnd,
        (int)shellDLL_DefView,  // Insert after DefView
        0, 0, 0, 0,
        SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE);
}
```

**Key Insight from Microsoft:**
> When the desktop is raised, we create a child WorkerW window that is z-ordered under the DefView that will render the wallpaper. The DefView window will draw mostly transparent with just the icons and text.

> **If your application forces the "raised desktop" state, it will now need to create its own WS_EX_LAYERED child HWND** that is z-ordered under the DefView window but above the WorkerW window.

### Potential Solution: DirectComposition + Layered Window

**Architecture:**
```
D2DPlayer.exe:
  ├─ DXGI Swap Chain (renders frames)
  ├─ DirectComposition Device
  ├─ Composition Visual (binds swap chain)
  ├─ Composition Target (binds to window)
  └─ WS_EX_LAYERED window (z-ordered correctly)
```

**Implementation Plan:**
1. Detect Windows 11 24H2 "raised desktop" mode
2. Create WS_EX_LAYERED window (not WS_EX_TRANSPARENT)
3. Use `SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA)` for full opacity
4. Parent to Progman, NOT WorkerW
5. Z-order under DefView using SetWindowPos
6. Bind DXGI swap chain to DirectComposition visual
7. Update via `dcompDevice.Commit()` after each frame

## Research Area 3: Lively Wallpaper's Approach

### Architecture Overview

Lively uses **3 different rendering strategies** depending on wallpaper type:

#### 1. Windows Forms + LibVLC (for videos/GIFs)

**Implementation:** `Lively.Player.Vlc` (separate process)

```csharp
// Lively.Player.Vlc/Form1.cs
public partial class Form1 : Form
{
    private LibVLC libVLC;
    private MediaPlayer mediaPlayer;

    // Uses LibVLCSharp's VideoView control (Windows Forms)
    videoView1.MediaPlayer = mediaPlayer;

    // Window is parented to WorkerW by main process
    // LibVLC handles all rendering internally
}
```

**Key Points:**
- ✅ Uses **Windows Forms** with embedded LibVLC control
- ✅ Simple, reliable, proven to work on Windows 11 24H2
- ✅ LibVLC handles all GPU acceleration internally
- ⚠️ Requires separate process for each wallpaper
- ⚠️ Less control over rendering pipeline

#### 2. DWM Thumbnail API (for desktop mirroring)

**Implementation:** `DwmThumbnailPlayer.cs`

```csharp
// Creates a "live preview" of another window
var dwmThumbnail = new DwmThumbnailWrapper(thumbnailSrc, Handle);
dwmThumbnail.Show();
dwmThumbnail.Update(sourceRect, destRect);

// Internally uses:
DwmRegisterThumbnail(dest, src, out thumbnail);
DwmUpdateThumbnailProperties(thumbnail, ref props);
```

**Key Points:**
- ✅ Hardware-accelerated by DWM
- ✅ Zero-copy rendering (DWM composites directly)
- ⚠️ Only works for mirroring existing windows
- ❌ Cannot be used for custom-rendered content

**References:**
- [DwmRegisterThumbnail - Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmregisterthumbnail)
- [DWM Thumbnail Overview - Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/dwm/thumbnail-ovw)

#### 3. WorkerW Parenting (for all other types)

**From `WinDesktopCore.cs`:**

```csharp
// 1. Send magic message to Progman to spawn WorkerW
NativeMethods.SendMessageTimeout(progman, 0x052C,
    new IntPtr(0xD), new IntPtr(0x1), ...);

// 2. Find WorkerW window
NativeMethods.EnumWindows((tophandle, topparamhandle) =>
{
    IntPtr p = NativeMethods.FindWindowEx(tophandle, IntPtr.Zero,
        "SHELLDLL_DefView", IntPtr.Zero);
    if (p != IntPtr.Zero)
    {
        workerW = NativeMethods.FindWindowEx(IntPtr.Zero, tophandle,
            "WorkerW", IntPtr.Zero);
    }
    return true;
}, IntPtr.Zero);

// 3. Detect Windows 11 24H2 "raised desktop"
isRaisedDesktopWithLayeredShellView = WindowUtil.HasExtendedStyle(
    progman, WS_EX_NOREDIRECTIONBITMAP);

// 4. Parent wallpaper window
if (isRaisedDesktopWithLayeredShellView)
{
    // Windows 11 24H2+ approach
    WindowUtil.SetWindowStyle(hwnd, WS_CHILD);
    WindowUtil.SetWindowTransparency(hwnd, 255);  // WS_EX_LAYERED
    WindowUtil.TrySetParent(hwnd, progman);       // Parent to Progman

    // Z-order: Under DefView, above WorkerW
    NativeMethods.SetWindowPos(hwnd, (int)shellDLL_DefView,
        0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE);
}
else
{
    // Windows 10 / older Windows 11 approach
    WindowUtil.TrySetParent(hwnd, workerW);
}
```

**Key Differences from WaBiBaBuSy:**
- Lively detects "raised desktop" mode and changes parenting strategy
- Uses **WS_EX_LAYERED** instead of WS_EX_TRANSPARENT on Windows 11 24H2
- Parents to **Progman** instead of WorkerW on Windows 11 24H2
- Uses `SetWindowTransparency(hwnd, 255)` for full opacity layered window

### Lively's Windows 11 24H2 Compatibility Fix

**From Lively's GitHub:**
> Windows 11 24H2 introduced a new underlying platform—known internally as Germanium—bringing major changes that inadvertently disrupted compatibility with many wallpaper apps.

> Core components were fully rewritten to adapt to platform changes introduced in Windows 11 24H2, fixing a critical issue where wallpapers could enter a restart loop on this version of Windows.

**Key Lesson:**
Lively had to completely **rewrite their desktop integration** for Windows 11 24H2. They now use:
- WS_EX_LAYERED windows (not WS_EX_TRANSPARENT)
- Parent to Progman (not WorkerW) on Windows 11 24H2
- Z-ordering via SetWindowPos relative to DefView

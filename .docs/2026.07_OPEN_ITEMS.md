## 2. Open decisions

- **TimingSynchronizer: wire up or delete.** The drift-telemetry loop is bug-fixed (session-scoped clients, CS1998) but has zero callers. Options: (a) wire into the orchestrator path and surface per-client drift in the topology UI, (b) delete it — the d2d_crossscreen path doesn't need it (deterministic math + clock offset).
- **`GroupedSequential`** enum value in `AnimationDistributionMode` — implement (groups of machines animate as one unit) or remove.
- **Legacy dead code** — GDI+ renderer stack (`CompositionRenderer`, `AnimationLayerRenderer`, `GifWallpaperRenderer`, `CrossScreenFrameRenderer`, `VideoWallpaperRenderer`, `ImageWallpaperRendererLibVLC`) and the server-side frame-streaming gRPC path (`StreamCrossScreenFrames`, `UseDistributedRendering`) are never invoked. Archive or delete.

## 3. Known limitations (accepted for now)

- **Background images / multi-image sources are not file-transferred to remotes** — only the primary animation file is distributed. Remote falls back to solid color / drops missing sources with a log warning. Fix = register additional contentIds + client-side download before apply.
- **Pattern/Traveling Colors unsupported for video content** (GIF/image only) — document as non-goal or implement.
- **Tearing on mismatched refresh rates (Win11 24H2+)** — Windows compositor limitation; workaround: match refresh rates (topology UI warns on mismatch).
- **Remote multi-monitor**: a remote machine renders on one monitor (`target_monitor_index`, default primary). Multiple monitors of one remote as separate topology nodes exists only partially.
- **IconZone issues from April** (`.docs/2026.04_IconZoneAnimation_TODO.md`) — some may have been fixed by the late-April commits (dynamic zone size, visual/occupancy padding split); re-verify each item against current code before working on them.

## 4. Tier 2 — Party experience features (priority order)

1. **Playlist / Party Mode** — rotate animation configs on a schedule (per-item duration, shuffle, timed "shows"). All infrastructure exists (content distribution, shared timestamps, session resume). **UX questions to settle first:**
   - Per-item duration vs. one global interval?
   - Hard-cut at rotation, or wait for the current traverse/lap to complete?
   - Do remotes follow automatically (natural via existing command path) — any per-client opt-out?
   - Where does the playlist live in the UI — own dialog, or a list in the Animation config?
2. **Bezel-crossing transition effects** — `SyncParameters.transition_effect` field exists but is unused. Deterministic glow/flash when the sprite crosses a node boundary (each player knows when the sprite enters/exits its slice).
3. **2D topology** — LAN parties have two facing table rows. `VirtualCanvasManager` is 1D left-to-right; add row concept (Y offsets, snake-order traversal: end of row 1 → start of row 2).
4. **Live position preview** — server computes the same deterministic math; show a moving dot on the topology canvas ("the fish is on Max's machine right now").
5. **Video feature parity** — pattern tiling + traveling colors for video.

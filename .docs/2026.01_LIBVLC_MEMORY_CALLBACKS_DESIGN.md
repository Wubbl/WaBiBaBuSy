# LibVLC Memory Callbacks for Composition System

**Date:** 2026-01-07
**Priority:** P1 - HIGH (Needed for GIF/Video composition)
**Status:** 📋 DESIGN - Implementation Needed

---

## Problem Statement

Current GIF rendering bypasses composition system due to TakeSnapshot() performance issues:
- **Disk I/O bottleneck:** 200ms per frame (PNG save/load)
- **Memory leaks:** Frame cache grows indefinitely
- **7% CPU usage:** Continuous disk operations
- **Breaks composition:** Can't use GIFs in cross-screen animations

**Goal:** Achieve LibVLC-level performance (<1% CPU, stable RAM) while supporting composition system.

---

## Solution: LibVLC Memory Callbacks

LibVLC provides direct memory access to decoded frames via callback functions. This is the same approach used by professional video editing software (Premiere, DaVinci Resolve).

### Architecture

```
LibVLC Decoder (Hardware Accelerated)
    ↓ (memory callback)
VideoWallpaperRenderer.VideoDisplay()
    ↓ (convert raw buffer to Bitmap)
_currentFrameBitmap (single frame in RAM)
    ↓
GetFrameAtPosition() returns current frame
    ↓
AnimationLayerRenderer.RenderForScreen()
    ↓
CompositionRenderer.Compose()
    ↓
D2DPlayerHost displays composed result
```

### Key Differences from TakeSnapshot()

| Approach | Disk I/O | CPU | Memory | Real-time |
|----------|----------|-----|--------|-----------|
| **TakeSnapshot()** | ✗ Yes (PNG) | 7% | Grows | ✗ No |
| **Memory Callbacks** | ✓ No | <1% | Stable | ✓ Yes |

## Implementation Steps

### Phase 1: Setup LibVLC Callbacks

**File:** `WaBiBaBuSy.WallpaperEngine/Renderers/VideoWallpaperRenderer.cs`

```csharp
// Add fields
private IntPtr _frameBufferPtr;
private int _videoWidth;
private int _videoHeight;
private Bitmap? _currentFrameBitmap;
private readonly object _framelock = new object();
private ManualResetEventSlim _frameReadyEvent = new ManualResetEventSlim(false);

// In InitializeAsync(), after creating MediaPlayer
private void SetupVideoCallbacks()
{
    // Tell LibVLC our desired output format (RGBA for easy Bitmap conversion)
    _mediaPlayer.SetVideoFormatCallbacks(
        VideoFormatSetup,
        VideoFormatCleanup
    );

    // Register callbacks for frame data
    _mediaPlayer.SetVideoCallbacks(
        VideoLock,    // Called when frame is about to be decoded
        VideoUnlock,  // Called when frame decode is complete
        VideoDisplay  // Called when frame should be displayed
    );
}

private uint VideoFormatSetup(ref IntPtr opaque, ref uint chroma,
    ref uint width, ref uint height, ref uint pitches, ref uint lines)
{
    // Store video dimensions
    _videoWidth = (int)width;
    _videoHeight = (int)height;

    // Request RGBA format (easiest to convert to Bitmap)
    chroma = BitConverter.ToUInt32(Encoding.UTF8.GetBytes("RV32"), 0);

    // Allocate buffer for frame data
    int bufferSize = (int)(width * height * 4); // 4 bytes per pixel (RGBA)
    _frameBufferPtr = Marshal.AllocHGlobal(bufferSize);

    pitches = width * 4;
    lines = height;

    _logger.LogInformation("LibVLC video format: {Width}x{Height}, RGBA, buffer={Bytes} bytes",
        width, height, bufferSize);

    return 1; // Success
}

private void VideoFormatCleanup(IntPtr opaque)
{
    // Free frame buffer
    if (_frameBufferPtr != IntPtr.Zero)
    {
        Marshal.FreeHGlobal(_frameBufferPtr);
        _frameBufferPtr = IntPtr.Zero;
    }
}

private IntPtr VideoLock(IntPtr opaque, ref IntPtr planes)
{
    // LibVLC is about to decode a frame - provide buffer to write to
    planes = _frameBufferPtr;
    return IntPtr.Zero;
}

private void VideoUnlock(IntPtr opaque, IntPtr picture, ref IntPtr planes)
{
    // Frame decode complete - planes points to frame data
    // Nothing to do here (we already have pointer in _frameBufferPtr)
}

private void VideoDisplay(IntPtr opaque, IntPtr picture)
{
    // Frame is ready for display - convert to Bitmap
    try
    {
        lock (_framelock)
        {
            // Dispose old frame
            _currentFrameBitmap?.Dispose();

            // Convert raw RGBA buffer to Bitmap
            _currentFrameBitmap = ConvertRawFrameToBitmap(
                _frameBufferPtr,
                _videoWidth,
                _videoHeight
            );

            _logger.LogTrace("Frame decoded and converted to Bitmap: {Width}x{Height}",
                _videoWidth, _videoHeight);

            // Signal that new frame is available
            _frameReadyEvent.Set();
        }
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error in VideoDisplay callback");
    }
}

private Bitmap ConvertRawFrameToBitmap(IntPtr bufferPtr, int width, int height)
{
    // Create Bitmap from raw RGBA data
    var bitmap = new Bitmap(width, height, PixelFormat.Format32bppArgb);

    var bitmapData = bitmap.LockBits(
        new Rectangle(0, 0, width, height),
        ImageLockMode.WriteOnly,
        PixelFormat.Format32bppArgb
    );

    try
    {
        // Copy raw frame data to bitmap
        int byteCount = width * height * 4;
        unsafe
        {
            Buffer.MemoryCopy(
                (void*)bufferPtr,
                (void*)bitmapData.Scan0,
                byteCount,
                byteCount
            );
        }
    }
    finally
    {
        bitmap.UnlockBits(bitmapData);
    }

    return bitmap;
}
```

### Phase 2: Update GetFrameAtPosition()

Replace TakeSnapshot() approach with callback-based approach:

```csharp
public Bitmap GetFrameAtPosition(long timestampMs)
{
    try
    {
        if (_mediaPlayer == null || _currentFrameBitmap == null)
            return new Bitmap(1, 1);

        lock (_framelock)
        {
            // Return current frame (LibVLC is playing in real-time)
            // Don't seek - just grab whatever frame is currently decoded
            return new Bitmap(_currentFrameBitmap);  // Clone to avoid threading issues
        }
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error getting current frame");
        return new Bitmap(1, 1);
    }
}
```

## Alternative Solutions

### Option 2: Shared Memory Buffer
- LibVLC writes to shared memory region
- Composition reads from same memory
- Zero copies, ultimate performance
- **Complexity:** Requires IPC setup

### Option 3: Pre-rendered Composition Video
- Compose animation once, save as video
- Play pre-rendered video with LibVLC
- **Limitation:** Only works for static/looping animations

### Option 4: All Composition in D2D Player
- Move composition logic to D2D player process
- Player receives metadata, does everything locally
- **Benefit:** No inter-process frame transfer
- **Trade-off:** More complex player process

---

## Recommendation

**Implement Option 1 (Memory Callbacks) first:**
- ✅ Solves immediate performance problem
- ✅ Works with existing composition architecture
- ✅ Industry-standard approach
- ✅ Relatively simple to implement (~4-6 hours)

**Future Enhancement: Shared Memory (Option 2)**
- After callbacks work, optimize with shared memory
- Eliminates Bitmap cloning overhead
- Gets us to professional-grade performance

## FIXED Issues

### 1. Player Crash on GIF Loop #4-5
**Root Cause:** `OnMediaEndReached` callback called `_mediaPlayer.Stop()` and `Play()` synchronously from LibVLC event thread.
**Fix:** Removed Stop/Play from callback. Looping now handled only by 95% position seek in `VideoDisplayCallback`.

### 2. DXGI Flip Model Buffer Rotation
**Root Cause:** D2D render target created once, never recreated after `Present()`. Buffers rotate with FlipSequential.
**Fix:** Added `RecreateD2DRenderTarget()` called after every `Present()`.

### 3. Explorer Crash (WS_EX_TRANSPARENT)
**Root Cause:** `WS_EX_TRANSPARENT` crashes explorer.exe on Windows 11 24H2+.
**Fix:** Replaced with `WS_EX_LAYERED + SetLayeredWindowAttributes(0xFF)`.

### 4. Only First Frame Visible (GIF Animation)
**Root Cause:** LibVLC's image demuxer treats GIFs as static images - decodes only frame 0 and re-displays it at max speed. Even with `--demux=avformat`, Duration reports as 100ms and EndReached fires after 1 display callback. Each Stop/Play restart only produces frame 0.
**Proof:** Buffer hash (`88247DB5`) was constant across ALL display callbacks. Position stuck at `0.000`.
**Fix:** GDI+ frame pre-extraction. `ExtractGifFrames()` loads all frames using `SelectActiveFrame()`, JPEG-compresses to `List<byte[]>` (~75MB vs ~4GB raw). `GetFrameAtPosition()` decodes on-demand with single-frame cache. LibVLC still used for MP4/video.
**Additional fixes during investigation:**
- Removed `_frameLock` deadlock (seeking LibVLC while holding lock)
- Removed `input-repeat=-1` (caused rapid restart loops)
- Fixed `OnMediaEndReached` to use `ThreadPool.QueueUserWorkItem`

## OPEN Issues

### ISSUE-004: GIF/MP4 Animation Speed Too Slow - FIXED (2026-02-26)

**Root Cause:** `SpeedMultiplier` from `AnimationLayerConfig` was never applied to GIF frame timing.

**Fix:** Native D2D composition in Player.D2D now applies `SpeedMultiplier` to elapsed time in `GetCurrentGifFrameIndex()`:
```csharp
long effectiveMs = (long)(elapsedMs * _gifSpeedMultiplier);
long loopedMs = effectiveMs % _d2dGifTotalDurationMs;
```
GIF frames are pre-cached as `ID2D1Bitmap[]` in GPU memory during load. Frame selection uses scaled elapsed time with modulo for seamless looping.

---

### ISSUE-005: GIF Doesn't Loop - FIXED (2026-02-26)

**Root Cause:** GIF looping depended on the old CompositionRenderer pipeline which had issues with elapsed time overflow and frame index getting stuck on the last frame.

**Fix:** Native D2D composition in Player.D2D uses modulo-based looping directly:
```csharp
long loopedMs = effectiveMs % _d2dGifTotalDurationMs;
```
This automatically wraps back to frame 0 when elapsed time exceeds total GIF duration, providing seamless infinite looping.

### ISSUE-006: GIF Frame Extraction Slow - FIXED (2026-02-07)

**Original Problem:** GDI+ `SelectActiveFrame()` took ~8s. First Magick.NET attempt was even slower (41875ms) because JPEG encoding 500 frames dominated the time.

**Fix:** Eliminated JPEG encode/decode entirely. Changed `VideoWallpaperRenderer.ExtractGifFrames()` from storing `List<byte[]>` (JPEG-compressed) to `Bitmap[]` (direct `ToBitmap()` from Magick.NET). This removes:
- JPEG encoding during extraction (the bottleneck - 500 frames x ~80ms each)
- JPEG decoding during playback in `GetFrameAtPosition`
- Single-frame decode cache (`_cachedGifFrameIndex` / `_cachedGifFrame`) - no longer needed

**Trade-off:** Higher memory usage (raw Bitmap ~800KB/frame vs JPEG ~70KB/frame), but much faster extraction and zero-overhead playback.

**NuGet packages:**
- `Magick.NET-Q8-AnyCPU` 14.10.3 (upgraded from 14.10.2 to fix Dependabot security alerts)
- `Magick.NET.SystemDrawing` 8.0.15
- `System.Drawing.Common` upgraded to 8.0.22

### ISSUE-007: Memory Leak in D2D Player - FIXED (2026-02-26)

**Root Cause:** The old GDI+ composition pipeline allocated and disposed `System.Drawing.Bitmap` objects every single frame:
1. `GetFrameAtPosition()` returned `new Bitmap(...)` clones each call
2. `ComposeForScreen()` created intermediate bitmaps per frame
3. `ConvertBitmapToD2D()` uploaded to GPU then the GDI+ bitmap was disposed - but D2D bitmaps leaked

**Fix:** Native D2D composition eliminates all per-frame allocation. GIF frames are extracted once during load as `ID2D1Bitmap[]` GPU-resident bitmaps. The render loop just calls `DrawBitmap(_d2dGifFrames[index])` - zero allocation, zero GDI+ involvement. Background images are also pre-cached as `ID2D1Bitmap`. Old resources are properly disposed via `DisposeNativeD2DResources()` when loading new content or during shutdown.

### ISSUE-002: UI Freeze on Animation Switch - FIXED (2026-02-26)

**Root Cause:** The old `HandleLoadAnimationCommand` disposed the CompositionRenderer synchronously which could block, and stale state from the previous animation wasn't fully cleaned up.

**Fix:** Native D2D composition in Player.D2D properly disposes old resources via `DisposeNativeD2DResources()` before creating new ones. The GIF path no longer creates a `CompositionRenderer` at all (which was the source of the blocking disposal). Loading a 2nd GIF cleanly replaces the first with no stale state.

### ISSUE-009: Horizontal Centering Broken in Center FitMode - FIXED (2026-02-07)

**Root Cause:** `InitializeAsync()` set `_currentVirtualX = 0` for centered content - left-aligned instead of centered. Vertical centering worked because `CalculateVerticalPosition()` used `_virtualCanvasHeight`, but there was no equivalent horizontal calculation.

**Fix:** Added `_screenWidth` field, stored during `CalculateAnimationDimensionsAsync()`. Changed centering to `_currentVirtualX = (_screenWidth - _animationWidth) / 2`. Works for all FitModes: Stretch gives offset 0 (correct), Center/Fit give positive offset (centered), Fill gives 0 or negative (extends beyond screen edges).

### ISSUE-010: LibVLC Unnecessary 10-Second Init for GIFs - FIXED (2026-02-07)

**Root Cause:** `InitializeAsync()` always initialized LibVLC (~10s) even for GIF files that use Magick.NET extraction.

**Fix:** Check file extension + `HeadlessMode` at start of `InitializeAsync()`. For `.gif` files in headless mode, set `_useMemoryCallbacks = true` and return immediately - skipping LibVLC entirely. `StartAsync()` already routes to `ExtractGifFrames()` for this case.

### ISSUE-011: Background Color From GIF Edge Pixels / User-Selectable - FIXED (2026-03-17)

**Fix:** Implemented `BackgroundColorDetector` service + UI controls for auto-detect and manual override.

**Implementation:**

- `MainWindowViewModel.cs` - `D2dBackgroundColor` property (default `#000000`), `IsAutoDetectBackground` toggle. Auto-detects on wallpaper select. `ApplyWallpaperWithDirect2DAsync()` uses detected/user color instead of hardcoded black.

- `CrossScreenConfigDialog.axaml` - "Auto-detect" button next to solid color hex input.

## Architecture Notes

### Render Pipeline Flow (Updated 2026-02-26):

**GIF Path (NEW - Native D2D Composition in Player.D2D):**
```
Load Phase (one-time):
  Magick.NET MagickImageCollection.Coalesce()
    ↓ For each frame: ToBitmap() → LockBits → ID2D1DeviceContext.CreateBitmap()
  GPU-resident ID2D1Bitmap[] (frames persist across presents)
  Background: ID2D1Bitmap (image) or Color4 (solid)
  Layout: CalculateAnimationLayout() (FitMode + centering)

Render Loop (zero allocation per frame):
  ID2D1DeviceContext.CreateBitmapFromDxgiSurface(backBuffer)
    ↓ Bind DeviceContext to current back buffer
  DrawBackground()
    ↓ D2D Clear() or DrawBitmap() for background
  GetCurrentGifFrameIndex(elapsed * SpeedMultiplier)
    ↓ Frame index from delay accumulator with modulo looping
  _d2dContext.DrawBitmap(_d2dGifFrames[index])
    ↓ GPU blit, zero-copy
  _d2dContext.Target = null
  _swapChain.Present()
```

**MP4/Video Path (Fallback - CompositionRenderer + GDI+):**
```
  LibVLC VideoDisplayCallback → _currentFrameBitmap
    ↓ GetFrameAtPosition(timestampMs)
  Clone bitmap
    ↓
  AnimationLayerRenderer.RenderForScreen()
    ↓ Crops to screen viewport with FitMode
  CompositionRenderer.ComposeForScreen()
    ↓ Composites background + animation
  D2DPlayer.ConvertBitmapToD2D()
    ↓ GDI+ Bitmap → D2D bitmap
  _d2dContext.DrawBitmap()
  _swapChain.Present()
```

**Key Improvement:** D2D DeviceContext persists across frames (no RecreateD2DRenderTarget needed).
Cached ID2D1Bitmaps survive across Present() calls. GIF path has zero per-frame allocation.

### Known Limitations (MVP)
- **Reconnection needs E2E validation** — auto-reconnection with backoff + session resume implemented 2026-07-07; the "<5s reconnection" target still needs measuring on a real network.
- **Video in legacy composition path** — the legacy `CompositionRenderer` path still returns a blank 320x240 bitmap from `VideoWallpaperRenderer.GetFrameAtPosition` before the first decoded frame. The native D2D video path (LibVLC → raw buffer → `CopyFromMemory` → `ID2D1Bitmap` in `Player.D2D/Program.cs`) is complete and is the production path.
- **Pattern mode unsupported for video content** — per-cell pattern rendering only works for GIF/image content, not native D2D video (see comment in `Player.D2D/Program.cs` render loop).
- **Tearing on secondary monitor with mismatched refresh rates (Win11 24H2+)** — When two local monitors run at different refresh rates (e.g. 165 Hz primary + 75 Hz secondary), the lower-refresh-rate panel shows visible tearing on horizontal-scrolling animations. Root cause: wallpaper windows are mandatorily layered (`WS_EX_LAYERED`) and parented to WorkerW (required to render behind desktop icons on 24H2+ — see Architectural Invariants in `CLAUDE.md`), which disqualifies them from DXGI independent flip. With composited present, DWM updates the secondary panel's framebuffer at the *primary* monitor's refresh cadence, producing scan-out misalignment on the slower panel. Confirmed 2026-05-02: setting both monitors to the same refresh rate in Windows display settings eliminates tearing entirely. Swap-chain side has been tuned as far as it can go (`Scaling.None`, `SwapEffect.FlipDiscard`, `FrameLatencyWaitableObject` + `MaximumFrameLatency=1`); remaining behaviour is a Windows compositor limitation, not an app bug. Workaround: match refresh rates at the OS level. The UI now shows each node's refresh rate in the network topology view and warns when a mismatch is detected on local monitors.

## Code Audit Findings (2026-07-07)

Verified against source during the July 2026 full-codebase audit. **Tier 1 fixes landed 2026-07-07** (see `.docs/plans/2026-07-07-tier1-reliability.md`); findings 1-4 and 7-10 are resolved, 5-6 and 11-12 remain open.

### Fixed 2026-07-18
6. ~~`TimingSynchronizer` drift loop still has no callers~~ — Deleted; replaced by passive drift telemetry — clients report clock offset + RTT via heartbeat, server stores on `ConnectedClient` + `DriftMonitor`, topology UI shows per-node ±Xms label. See `.docs/plans/2026-07-18-drift-telemetry-design.md`.

### Fixed 2026-07-07 (Tier 1 reliability work)
5. ~~Drift always computed as 0~~ — `ClientAnimationRenderer` now passes `localElapsedMs` into `CalculateClockOffsetMs`.
11. ~~Float precision stutter after days of uptime~~ — `MovementCalculator` folds elapsed time into each movement's period in double before any float math (Linear/Bounce/SineWave/Circular/RandomWalk); covered by 40-days-uptime unit tests.
12. ~~RandomWalk teleports at seed-rotation boundaries~~ — boundary waypoints are pinned to the previous iteration's seed so consecutive segments share them; covered by continuity + variation unit tests.
1. ~~No clock-offset estimation~~ — heartbeats now feed an NTP-style min-RTT `ClockOffsetEstimator`; incoming command timestamps are converted to local-clock terms at the sync-stream boundary.
2. ~~Remote clients get an amputated MovementConfig~~ — full `MovementConfig`/`AnimationLayerConfig`/`BackgroundLayerConfig` now travel as JSON in `SyncParameters` (fields 18-21).
3. ~~Simultaneous mode silently becomes Sequential on remotes~~ — per-monitor mode no longer applies the spanning canvas/offset overrides.
4. ~~No reconnection logic~~ — 1s..30s exponential backoff reconnect on stream loss or 3 heartbeat failures; server resumes the active animation on re-register.
7. ~~Silent port-bind failure~~ — server awaits `StartAsync()`; bind errors surface.
8. ~~Concurrent gRPC stream writes drop commands~~ — per-client `SemaphoreSlim` write serialization.
9. ~~Dead clients linger in topology~~ — 10s sweep removes clients with heartbeat >30s old.
10. ~~Dispose() deadlock risk~~ — client and server host Dispose use thread-pool waits with timeouts.

**Verified sound:** D2D render loop (resource disposal, DWM frame-latency pacing, exception containment, stdin IPC parsing), local Sequential/Simultaneous canvas math, late-join epoch back-dating.

**Remaining remote-parity caveats:** background *images* and multi-image sources are not file-transferred to clients (remote falls back to solid color / drops missing sources with a warning); only the primary animation file is distributed.

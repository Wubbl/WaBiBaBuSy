### Known Limitations (MVP)
- **No auto-reconnection** — `WallpaperSyncClient` has no reconnect logic at all (neither basic retry nor exponential backoff). On connection loss the client simply sets `IsConnected=false`. The "<5s reconnection" target requires implementing reconnection first.
- **Video in legacy composition path** — the legacy `CompositionRenderer` path still returns a blank 320x240 bitmap from `VideoWallpaperRenderer.GetFrameAtPosition` before the first decoded frame. The native D2D video path (LibVLC → raw buffer → `CopyFromMemory` → `ID2D1Bitmap` in `Player.D2D/Program.cs`) is complete and is the production path.
- **Pattern mode unsupported for video content** — per-cell pattern rendering only works for GIF/image content, not native D2D video (see comment in `Player.D2D/Program.cs` render loop).
- **Tearing on secondary monitor with mismatched refresh rates (Win11 24H2+)** — When two local monitors run at different refresh rates (e.g. 165 Hz primary + 75 Hz secondary), the lower-refresh-rate panel shows visible tearing on horizontal-scrolling animations. Root cause: wallpaper windows are mandatorily layered (`WS_EX_LAYERED`) and parented to WorkerW (required to render behind desktop icons on 24H2+ — see Architectural Invariants in `CLAUDE.md`), which disqualifies them from DXGI independent flip. With composited present, DWM updates the secondary panel's framebuffer at the *primary* monitor's refresh cadence, producing scan-out misalignment on the slower panel. Confirmed 2026-05-02: setting both monitors to the same refresh rate in Windows display settings eliminates tearing entirely. Swap-chain side has been tuned as far as it can go (`Scaling.None`, `SwapEffect.FlipDiscard`, `FrameLatencyWaitableObject` + `MaximumFrameLatency=1`); remaining behaviour is a Windows compositor limitation, not an app bug. Workaround: match refresh rates at the OS level. The UI now shows each node's refresh rate in the network topology view and warns when a mismatch is detected on local monitors.

## Code Audit Findings (2026-07-07)

Verified against source during the July 2026 full-codebase audit. Ranked by severity.

### P0 — Break multi-machine sync (the core LAN-party use case)
1. **No clock-offset estimation** — the shared start timestamp (`MainWindowViewModel.cs:3011`, `Player.D2D/Program.cs:3404`) assumes all Windows clocks agree. Heartbeat responses carry `ServerTimestamp` but the client discards it (`WallpaperSyncClient.cs:295`). Two machines whose clocks differ by >50ms are permanently offset by that amount. Fix: NTP-style 4-timestamp offset/RTT estimation over the existing heartbeat, apply offset when converting `shared_start_timestamp_ms` to the local epoch.
2. **Remote clients get an amputated `MovementConfig`** — `MainWindowViewModel.cs:1985-1991` rebuilds `new MovementConfig { Type, SpeedPixelsPerSecond }` from the int `movement_type`; `Reversed`, `Endless`, `DirectionAngleDegrees`, wave/orbit params, `StartX/Y`, `RandomStepIntervalMs`, `IterationStepCount` all revert to defaults. Also `TargetHeight` is forced to screen height on remotes (line 1976) while local players use the configured value → different `MovementCalculator` inputs → different paths. Fix: send full `MovementConfig` as JSON (like `pattern_json`/`color_grading_json`) plus the `AnimationLayerConfig` sizing fields.
3. **Simultaneous mode silently becomes Sequential on remote clients** — server always sends full canvas width + nonzero offset (`MainWindowViewModel.cs:3046-3047`); client passes them as explicit overrides (`MainWindowViewModel.cs:2003-2004`) which defeat the `perMonitorMode` fallback in `D2DCompositionService.cs:156-159`. Violates the CLAUDE.md distribution-mode invariant for remotes; local monitors are correct.
4. **No reconnection logic** — `WallpaperSyncClient.cs:751-754`: when the sync stream dies, the exception is logged, the task exits, `IsConnected` stays `true`, no event fires, nothing retries. Heartbeat failures likewise swallowed (lines 258-261).

### P1 — Correctness / robustness
5. **Drift always computed as 0** — `ClientAnimationRenderer.cs:217` passes `sync.ExpectedPositionMs` into `CalculateClockOffsetMs(...)` (x−x=0) instead of `localElapsedMs`; drift handlers receive a useless magnitude.
6. **`TimingSynchronizer.StartTimingSyncAsync` is dead code** — zero callers; the D2D cross-screen path has no runtime drift monitoring at all, only the initial shared timestamp. Latent bugs if wired up: iterates `GetAnimatingClients()` instead of `session.ClientIds`; `async` without `await`.
7. **Server reports "started" even if the port bind fails** — `WallpaperSyncServerHost.cs:94-99` fire-and-forgets `_host.RunAsync()`, sleeps 500ms, sets `_isRunning = true` unconditionally. Await `StartAsync()` instead. `Dispose()` also does sync-over-async (`.Wait()`).
8. **Concurrent writes to one gRPC response stream can drop commands** — `WallpaperSyncService.cs:562-581` has no per-client write serialization; overlapping `WriteAsync` throws and the command is silently lost. Add per-client `SemaphoreSlim`.
9. **Dead clients linger in topology** — `LastHeartbeat` is recorded (`WallpaperSyncService.cs:161,217`) but never swept; removal only happens on stream teardown. Power-loss/sleep clients stay "connected". Add a periodic `LastHeartbeat > 3×interval` sweep.
10. **`Dispose()` deadlock risk** — `WallpaperSyncClient.cs:1195` and `WallpaperSyncServerHost` block on async work (`.Wait()`) without `ConfigureAwait(false)`; can deadlock the UI thread on shutdown.

### P2 — Long-run visual quality
11. **Float precision stutter after days of uptime** — `MovementCalculator.cs:67-68` computes unbounded `elapsedSec`/`traveledDistance` as floats before the modulo; at ~5 days uptime resolution is ~31ms → visible position quantization. The Endless branch (`Program.cs:2240-2252`) already folds phase into a bounded range — apply the same treatment to Linear/SineWave/Bounce/Circular. Stays synchronized (same inputs everywhere), but gets choppy.
12. **RandomWalk teleports at seed-rotation boundaries** — `MovementCalculator.cs:213-220`: at step `k×IterationStepCount` the waypoint switches from `waypoint(oldSeed, N)` to `waypoint(newSeed, N)` → discontinuous jump on all machines simultaneously. Pin the last waypoint of an iteration to equal the first of the next.

**Verified sound:** D2D render loop (resource disposal, DWM frame-latency pacing, exception containment, stdin IPC parsing), local Sequential/Simultaneous canvas math, late-join epoch back-dating.

### Known Limitations
- **Pattern / Traveling Colors unsupported for video content** — per-cell rendering only works for GIF/image content, not native D2D video (see the render loop in `Player.D2D/Program.cs`).
- **`FaceTravelDirection` not visible in `exactFrame` stills** — facing comes from the previous live frame's position; check it with live `probe` captures.
- **Remote multi-monitor** — a remote machine renders on one monitor (`target_monitor_index`).
- **Tearing on secondary monitor with mismatched refresh rates (Win11 24H2+)** — When two local monitors run at different refresh rates (e.g. 165 Hz primary + 75 Hz secondary), the lower-refresh-rate panel shows visible tearing on horizontal-scrolling animations. Root cause: wallpaper windows are mandatorily layered (`WS_EX_LAYERED`) and parented to WorkerW (required to render behind desktop icons on 24H2+ — see Architectural Invariants in `CLAUDE.md`), which disqualifies them from DXGI independent flip. With composited present, DWM updates the secondary panel's framebuffer at the *primary* monitor's refresh cadence, producing scan-out misalignment on the slower panel. Confirmed 2026-05-02: setting both monitors to the same refresh rate in Windows display settings eliminates tearing entirely. Swap-chain side has been tuned as far as it can go (`Scaling.None`, `SwapEffect.FlipDiscard`, `FrameLatencyWaitableObject` + `MaximumFrameLatency=1`); remaining behaviour is a Windows compositor limitation, not an app bug. Workaround: match refresh rates at the OS level. The room view shows each node's refresh rate and warns on a local mismatch.

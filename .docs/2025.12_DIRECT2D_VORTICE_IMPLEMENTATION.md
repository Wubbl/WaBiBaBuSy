# Direct2D Rendering Architecture with Vortice.Windows

**Date:** 2025-12-21
**Status:** Implementation In Progress
**Author:** Claude (Opus 4.5)

---

## Executive Summary

This document describes the architectural decision to migrate WaBiBaBuSy's rendering pipeline from WinForms `PictureBox` (GDI+) to true Direct2D using the Vortice.Windows library. This enables hardware-accelerated 60 FPS composite animation rendering with minimal CPU/GPU overhead.

---

## Problem Statement

The original "Direct2D" renderer was a misnomer - it actually used:
- WinForms `Form` + `PictureBox`
- GDI+ for bitmap composition (`System.Drawing.Graphics`)
- `Application.DoEvents()` hack for message pumping
- `PictureBox.Refresh()` for forced repaints

**Issues:**
- No hardware acceleration
- CPU-bound composition
- GC pressure from per-frame `Bitmap` allocations
- Frame rate inconsistencies
- Threading issues with WinForms message pump

---

## Technology Evaluation

Three options were evaluated for proper hardware-accelerated 2D rendering:

### Option 1: SkiaSharp

| Aspect | Evaluation |
|--------|------------|
| GPU Support | OpenGL/Vulkan via ANGLE |
| Platform | Cross-platform |
| .NET Support | Mature, used by Avalonia/MAUI |
| **Verdict** | Inconsistent GPU acceleration on Windows Desktop |

**Rejected because:** WinUI3/UWP GPU acceleration issues, ANGLE dependency, .NET 8.0 crashes reported.

### Option 2: WPF CompositionTarget.Rendering

| Aspect | Evaluation |
|--------|------------|
| GPU Support | DirectX via MIL |
| Platform | Windows only |
| .NET Support | Built-in since .NET 3.0 |
| **Verdict** | Frame rate throttles to ~50fps when idle |

**Rejected because:** Known frame rate throttling bug, WPF overhead, potential Avalonia conflicts.

### Option 3: Direct2D via Vortice.Windows (Selected)

| Aspect | Evaluation |
|--------|------------|
| GPU Support | Direct3D 10.1/11.1 native |
| Platform | Windows only |
| .NET Support | Active, targets .NET 9/10 |
| **Verdict** | Best fit for Windows desktop wallpaper |

**Selected because:**
- True hardware acceleration
- Native Windows API (same as DWM)
- `ID2D1HwndRenderTarget` designed for this use case
- Full render loop control
- Active development (v3.8.1)

| Component | Responsibility |
|-----------|----------------|
| `D2DRenderContext` | Manages Direct2D/WIC factories, creates resources |

| `D2DBackgroundLayerRenderer` | Renders background (solid, stretched, tiled) |
| `D2DAnimationLayerRenderer` | Renders moving animation layer with culling |
| `D2DGifFrameProvider` | Loads GIF frames into GPU memory (ID2D1Bitmap) |
| `D2DImageProvider` | Loads static images into GPU memory |
| `D2DCompositor` | Orchestrates render loop and layer composition |

## Render Loop Flow

```
1. Timer fires (every ~16ms for 60 FPS)
   │
2. RenderFrame() callback
   │ Calculate: elapsedMs = stopwatch.ElapsedMilliseconds
   │
3. BeginDraw()
   │
4. Render Background Layer
   │ - Clear(backgroundColor) or DrawBitmap(background)
   │
5. Update Animation Position
   │ - X = -width + (elapsedMs / 1000.0 * pixelsPerSecond)
   │
6. Visibility Culling
   │ - Skip if animation not visible on screen
   │
7. Get Animation Frame
   │ - GIF: _frameCache[CalculateFrameIndex(elapsedMs)]
   │ - Image: _cachedImage
   │
8. Render Animation Layer
   │ - DrawBitmap(frame, destRect, opacity, interpolation, sourceRect)
   │
9. EndDraw()
   │
10. Presented to screen via DWM
```

## Memory Management

### GPU-Resident Bitmaps

All image data is loaded into `ID2D1Bitmap` objects which reside in GPU memory:

```csharp
// Load GIF frames into GPU memory
for (int i = 0; i < frameCount; i++)
{
    using var wicFrame = decoder.GetFrame(i);
    using var converter = wicFactory.CreateFormatConverter();
    converter.Initialize(wicFrame, PixelFormat.Format32bppPBGRA);

    _frameCache[i] = renderTarget.CreateBitmapFromWicBitmap(converter);
}
```

### No System.Drawing.Bitmap in Hot Path

The old implementation created `System.Drawing.Bitmap` objects every frame:

```csharp
// OLD - BAD (GC pressure)
var frame = new Bitmap(width, height);
using (var g = Graphics.FromImage(frame))
{
    // Compose...
}
_pictureBox.Image = frame;  // Queues previous for GC
```

The new implementation reuses GPU bitmaps:

```csharp
// NEW - GOOD (no allocations in hot path)
renderTarget.BeginDraw();
renderTarget.Clear(backgroundColor);
renderTarget.DrawBitmap(_cachedFrame, destRect);
renderTarget.EndDraw();
```

### Window Hierarchy (Windows 11 24H2+)

```
Progman (Desktop)

└── D2DWallpaperWindow (Our window - z-ordered below DefView)
```

### Window Setup

```csharp
// 1. Create borderless window
var hwnd = CreateWindowEx(
    WS_EX_LAYERED | WS_EX_TOOLWINDOW,
    className,
    "",
    WS_POPUP | WS_VISIBLE,
    bounds.X, bounds.Y, bounds.Width, bounds.Height,
    IntPtr.Zero, IntPtr.Zero, IntPtr.Zero, IntPtr.Zero);

// 2. Parent to Progman
SetParent(hwnd, progman);

// 3. Z-order below SHELLDLL_DefView
SetWindowPos(hwnd, shellDefView, 0, 0, 0, 0,
    SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE);

// 4. Create render target
_renderTarget = factory.CreateHwndRenderTarget(
    new RenderTargetProperties(),
    new HwndRenderTargetProperties { Hwnd = hwnd, PixelSize = size });
```

## GIF Frame Timing

GIF frame delays are extracted from WIC metadata:

```csharp
private int ExtractFrameDelay(IWICBitmapFrameDecode frame)
{
    using var reader = frame.GetMetadataQueryReader();

    // GIF frame delay is in 1/100ths of a second
    var delay = reader.GetMetadataByName("/grctlext/Delay");
    int delayMs = (delay is ushort d) ? d * 10 : 100;

    // Minimum 10ms (browsers do this too)
    return Math.Max(delayMs, 10);
}

public ID2D1Bitmap GetFrameAtPosition(long elapsedMs)
{
    // Loop elapsed time to total animation duration
    long loopedMs = elapsedMs % _totalDurationMs;

    // Find frame for this timestamp
    long accumulated = 0;
    for (int i = 0; i < _frameCount; i++)
    {
        accumulated += _frameDelaysMs[i];
        if (loopedMs < accumulated)
            return _frameCache[i];
    }

    return _frameCache[0];
}
```

## Performance Characteristics

### Target Metrics

| Metric | Target | Method |
|--------|--------|--------|
| Frame Rate | 60 FPS | Timer-based render loop |
| CPU Usage | <5% | GPU offload, no GC pressure |
| GPU Usage | <15% | Efficient bitmap blitting |
| Memory | Stable | Pre-cached GPU bitmaps |
| Latency | <16ms/frame | Direct render, no composition |

### Optimization Techniques

1. **Pre-cache all GIF frames** - Load once, render many
2. **GPU-resident bitmaps** - No CPU↔GPU transfers per frame
3. **Visibility culling** - Skip off-screen animation regions
4. **Single render target** - Reuse across frames
5. **No intermediate bitmaps** - Render directly to window

## Error Handling

### Device Lost Recovery

```csharp
private void RenderFrame()
{
    if (_deviceLost)
    {
        RecreateResources();
        _deviceLost = false;
    }

    try
    {
        _renderTarget.BeginDraw();
        // Render...
        var result = _renderTarget.EndDraw();

        if (result == D2DERR_RECREATE_TARGET)
        {
            _deviceLost = true;
        }
    }
    catch (SharpGenException ex) when (ex.HResult == D2DERR_RECREATE_TARGET)
    {
        _deviceLost = true;
    }
}
```
